# Q30 native matrix census draft

`Q30MatrixCensusProbe.java` is a scratch-only diagnostic for plan-4 seeds 7, 10387, and 10014. It constructs each real `Rb30Generator` candidate, runs CircuitJS analysis, and requests exactly one accepted solver step. It does not route a board, prove healthy/fault behavior, settle, admit, or qualify a generated board.

The reported `postStepJacobianComponents` are exact nonzero bipartite row/column support components in the live CircuitJS matrix after that step (`r<row-count>c<column-count>`). Keeping row and column vertices distinct matters because `simplifyMatrix` can map them independently. These numeric components can identify possible matrix blocks, but are not a symbolic stamp graph. The accepted nonlinear-step LU factors are not retained by `CirSim`; the probe therefore factors only a cloned matrix for diagnostics. `diagnosticLuFactorComponents` describe that cloned factor array and remain exploratory; use raw post-step Jacobian components for block candidates. The live solver matrix is never factored by the diagnostic path. Each seed runs in a private simulator; its external supplies are disconnected, exact candidate elements are deleted, remaining element ownership is checked, solver work is retired, and the previous `CircuitElm.sim` and localization map are restored in `finally`.

The probe expects plan epoch 4 and package counts 37/20/40. To run later, add this class to the maintained native contract suite list and give it the same source/build path as the other contract tests, then invoke the maintained verifier with only the census suite selected. Do not treat its `PASS: Q30 matrix census probe ... qualification=NOT_RUN` marker as any Q30 acceptance evidence. No build or execution has been performed on this draft.
