## Electrical interpretation and mapping limit

The likely large block is the grounded control domain; the small block is the isolated load domain. `Rb30Generator.construct` makes J1 and JSx return to `CTRL_RETURN`, attaches `GroundElm` to that net, and makes JLOAD span `LOAD12`/`LOAD_RETURN` (`Rb30Generator.java:133–145`). Each Kx relay has control/coil posts on `RAIL5`, `COIL_LOW`, and `CTRL_RETURN`, while its contact posts use `LOAD12`, `NC_x`, and `OUT_x`; JOx loads `OUT_x` to `LOAD_RETURN`, and output indicators also return to `LOAD_RETURN` (`Rb30Generator.java:204–215, 258–282`). `ServiceRelayElm.doStep` stamps the coil and contacts as separate equations, with no coil-to-contact matrix term. `findUnconnectedNodes`/`connectUnconnectedNodes` may add a 100 MΩ reference shunt to the otherwise floating load domain; because node 0 is omitted from the unknowns, that grounding stamp adds a diagonal term and does not couple the domains (`CirSim.java:2610–2641`). The pattern and size changes across one/two-channel and indicator variants support this interpretation. The same Kx object can therefore own rows/columns in both blocks without electrically joining its coil to its contacts.

The requested exact member-to-ID mapping is **not present in the retained evidence**. The census log stores only block row/column counts, not member indices or `RowInfo`; the adjacent-factor profile stores aggregate dimensions/counters, not the matrices. So the 8/12/14-member components cannot yet be attributed row-by-row to JLOAD, Kx, JOx, or individual nodes. Treat “control/load” as a source-grounded interpretation, not a measured member list.

A focused future probe can invert the live maps immediately after one accepted step. In `simplifyMatrix`, `mapCol` is assigned to each `ROW_NORMAL` variable, but `mapRow` is assigned to each retained equation and dropped rows receive `-1` (`CirSim.java:2918–2957`). Build separate inverse tables: for each full index `i`, add equation `i` to reduced row `mapRow` when `mapRow >= 0`; add unknown `i` to reduced column `mapCol` only when `type == ROW_NORMAL && mapCol >= 0`. Do not pair equal reduced row/column indices. For full indices below `nodeList.size()-1`, resolve node `i+1` through `nodeList` and print `CircuitNode.internal` plus each `CircuitNodeLink` element/post index; resolve board IDs by identity through `candidate.backing`. For source indices, subtract `nodeList.size()-1` and read the owner from `voltageSources[]`, then resolve its stable component ID by identity. Capture before LU mutates the matrix. This gives exact row and column sets and makes the “control/load” attribution testable without a full qualification run.

The one-step census is not representative of the later installed proof graph. The retained normal profile reports actual factor dimensions 71–81 (mostly 75), versus this seed-7 construction census at 58; its separate logical census figure is 58. Do not treat that as a row-member list or project the 46/12 split onto the installed graph. The current profile also sampled 745,131 factors and found only 14 exact inputs among 729 adjacent pairs (1.92%), so caching a prior factorization is a separate, weak opportunity.

## Generic LU split feasibility

A block factorization could be exact only with stronger evidence and careful index preservation. `lu_factor` currently finite-checks every input cell, rejects all-zero rows, selects pivots in global column order with the later-row `>=` tie rule, substitutes `1e-18` for a zero pivot, and finite-checks arithmetic (`CirSim.java:8021–8105`). `lu_solve` consumes the global row-pivot vector and RHS order. Any split must still inspect/reject nonfinite values outside blocks, verify there are no cross-block nonzeros, preserve all pivot/tie/zero behavior, and return factors/permutations compatible with the existing solve and full-variable restoration (`CirSim.java:3387–3398, 3488–3510`).

The row and column member sets may differ even when each connected component has equal row and column counts. Reordering each block into a compact square submatrix can change global pivot eligibility/order, `ipvt`, signed arithmetic, and final bits; applying a separate column permutation also requires undoing it when `lu_solve` maps `rs` through `mapCol`. Only if exact member sets establish an order-preserving layout (or a rigorously remapped algorithm matches the existing global pivot sequence) is a semantics-preserving split plausible. Zero/tied pivots are particularly important because the legacy zero-pivot fallback can select rows outside the active numeric component.

The current right-looking LU already avoids much cross-block arithmetic: it skips exact-zero lower multipliers and updates only columns with nonzero pivot-row entries. Its remaining broad work is the full finite/all-zero scan and per-column pivot search. A dense component discovery adds another O(n²) pass; extracting/copying block arrays and restoring global factors adds O(n²) traffic/allocation. For the census sizes, ideal block membership could reduce pivot-candidate visits by roughly 30–34%, but it would not remove the full finite scan and is not a prediction of wall-time gain. The sparse trailing updates already largely scale with within-block nonzeros, so textbook cubic split estimates overstate likely savings.

Each nonconverged nonlinear subiteration restores `origMatrix`, calls each model's `doStep`, then factors the newly stamped matrix; a later converged subiteration breaks before LU (`CirSim.java:3347–3396`). A numeric partition from one accepted step is therefore unsafe to cache. Runtime mutations and source changes require analysis/invalidation (`CirSim.java:2272–2275`); temporary measurement installs an overlay, analyzes, then removes it and analyzes/restores again (`CirSim.java:6630–6679`). A generic cache would need graph/epoch ownership and invalidation through all those paths. Recomputing numeric components per trial is possible, but the O(n²) scan can consume the pivot-scan savings. Tracking structural stamp support could avoid rescans, but it must conservatively include dynamic stamps and add newly observed couplings before each factor; that is a new proof obligation, not established by these snapshots.

**Assessment:** the electrical partition is plausible and worth exact member attribution at both construction and installed-proof states. The current data do not show enough to justify a generic block solver or factor cache. First retain row/column membership and measure partition stability and overhead on actual routed proof matrices; any candidate must preserve global pivot semantics and all finite/singular behavior, with the unchanged solver as a fail-closed fallback. No source, build, test, or gate was changed or run for this audit.
