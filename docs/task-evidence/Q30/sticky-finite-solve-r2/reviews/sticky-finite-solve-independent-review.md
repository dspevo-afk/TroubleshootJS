## Algebra and correctness boundary

The candidate takes one complete finite census of `b[0..n)` before the original pivot permutation. If any entry is NaN or either infinity, it keeps the historical dense loops throughout. With an initially finite RHS, the pivot loop only permutes finite values. Each forward row copies a still-finite future RHS slot, accumulates in the same ascending `j` order, stores `tot`, then permanently clears the flag if that stored value is nonfinite. Back substitution likewise clears the flag after each stored division. Thus a later row containing `0 * Inf` or `0 * NaN` uses the dense path. If a forward/back accumulation first becomes nonfinite within a row, skipped zero terms in that row still multiply finite prior RHS values; their signed-zero contribution cannot change a finite numeric result or recover an infinity/NaN. NaN/Inf matrix coefficients are not skipped (`coefficient != 0` is true), so they still propagate. Signed-zero bit identity is intentionally excluded; numeric zero, finite values, infinity sign, and NaN classification remain compared.

This reasoning matches current callers: `runCircuitOwned` passes separately allocated `circuitMatrix` and `circuitRightSide` (allocation at CirSim.java 2813–2820; solve at 3395–3399); `invertMatrix` uses a separate local RHS (8866–8880); current tests also pass separate arrays. The production solve path validates the returned RHS and then validates full solution values before model mutation (`applySolvedRightSide`, 3485–3494). There are no other current production `lu_solve` call sites. The method has no explicit no-alias contract, so preserve these disjoint caller relationships on rebase.

## Cost and rebase recommendation

The design adds O(n) finiteness calls once per solve and one exact-zero branch for each triangular coefficient; it does not allocate or cache. Each exact zero skips a multiply and subtract while preserving nonzero term order. Dense/fill-heavy factors retain the same O(n²) visits and add the branch; sparse factors may save arithmetic. The relevant sparsity is in the factored triangular rows/columns, not the stamped matrix.
