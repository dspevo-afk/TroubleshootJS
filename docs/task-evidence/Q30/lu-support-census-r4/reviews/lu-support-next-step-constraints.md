# LU support census: requirements before block-aware work

**Current decision: the existing census can establish sampled opportunity, not authorize a block fast path.** This is source review only; no actual proof-census result was supplied. In particular, `recordZeroPivotFallback` exists in `Q30LuSupportCensus` but has no caller, and `declareZeroPivotObservationAvailable` is never invoked (`Q30LuSupportCensus.java:52–58, 131–139`; source-wide search). Therefore `zeroPivotObservationAvailable` remains false and `Opportunity.exact` cannot become true (`:715–719`). Post-factor equality to `1e-18` is explicitly only a conservative risk check (`:142–169`), not an observed fallback.

A bounded candidate, if later justified, belongs only in the owned nonlinear factor path. Keep the all-zero-row preflight and the global `k=0..n-1` loop. Do not permute or factor blocks separately. A per-factor certificate must describe the exact post-`doStep` matrix (or a conservative support superset with complete writer coverage): `n`; ordered bipartite row/column membership and nonzero row indices per column; balanced component row/column counts; no cross-component edge; all input values finite; and the current owner/matrix generation. If a partition is reused from `origMatrix`, prove no current cross-edge crosses it; `origMatrix` alone is not enough after dynamic stamps. Rebuild or fall back on any uncertain owner, support change, fault/retry/overlay, or analysis replacement.

At each global pivot, track row-component labels through the exact existing swaps. Candidate rows from the active column’s component must be visited in ascending *current global row index* and compared with the same `abs(q) >= largest` rule. Cross-component entries may be omitted only when certified zero and an in-component pivot has strictly positive magnitude; zeros then cannot win or tie. If that component has no positive candidate, run the original complete `i=k..n` scan before swapping: its all-zero `>=` tie selects the last remaining row, which controls `ipvt` and the `1e-18` fallback. Keep `ipvt`, pivot order, row swaps, `lowerRows`/`upperColumns` order, arithmetic and cleanup unchanged. Do not skip numeric updates based on a census count. Existing sparse workspace already updates only rows/columns whose values are nonzero; focus any experiment on proven scan reduction.

Each actual selected sample should retain: exact pre-factor support and finite status; current-vs-original added/removed/cross edges; full `ipvt`; per-pivot selected row, pivot value, and whether the exact zero branch ran; and complete success/failure plus workspace/token cleanup. Signed-zero edge classification is fine for a support graph, but the current `signedZeroDifferences` is only a count, not a bitwise trace. A scan-only optimization must leave matrix cells untouched when skipping certified zeros; parity tests should compare full factored matrix/RHS bits, pivots, outcome and callback-visible result against the original kernel, including signed zeros, equal-magnitude ties, all-zero pivot columns and nonfinite/failure cases.

Today `beginFactor` samples every 4096th call and caps records at 256 (`:13–15, 65–88`); `completeCapture` means the selected records completed, not that every factor call was observed (`:230–238`). `recordPreFactor` reads both full matrices and builds support components (`:92–122, 285–342`), so running it for every call would itself scan O(n²) before LU. Its graph stores component membership/counts, not cell values or tie sets; `ipvt` replay is retrospective and only recorded after successful factors (`:171–205, 533–595, 656–721`). These data can rank experiments but cannot gate unsampled production calls.

For state safety, keep any certificate ephemeral to one matrix/factor call and the existing `LuFactorizationWorkspace`; preserve its `reset`/`finally clear` path (`CirSim.java:8123–8143`). Always finish selected census tokens on success/failure and clear the exact verifier-owned census pointer in `finally` (`CirSim.java:3403–3457`; `Q30CoordinatorQualificationVerifier.java:953–972`). Any incomplete sample, dropped record, failed factor, cross-group pivot, zero fallback, nonfinite input, uncertain support writer or cleanup error is a full-kernel/no-optimization case. No numerical saving or qualification result is claimed here.
