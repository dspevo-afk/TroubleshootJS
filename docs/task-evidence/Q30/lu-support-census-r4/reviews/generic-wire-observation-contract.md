# Generic wire-current observation contract audit

Decision: **No-go for a new generic deferral gate using the existing contracts.** They identify owned operations and accepted boundaries, but they do not declare which callbacks read `WireElm.getCurrent()` or whether that value must be fresh at the callback boundary. The existing `canDelayWireProcessing()` gate is specifically a wire-scope check; it is not proof that arbitrary accepted-step listeners are wire-current independent.

## Accepted-step owners and order

`CirSim.runCircuitOwned` builds `iterationElements` from every element except exact `WireElm` instances (`CirSim.java:3319-3320`). After an accepted solve, it advances time and calls each `stepFinished()` (`3440-3441`), refreshes wire currents before scope sampling only when `canDelayWireProcessing()` is false (`3442-3448`), saves accepted node voltages, then calls `solverExecutor.accepted(operation)` (`3449-3452`). For an owned temporal operation, if wire processing is delayable, `calcWireCurrents()` runs only after accepted callbacks and before the next accepted step (`3455-3461`, especially `3458`). The ordinary UI path refreshes at the end of the batch (`3479-3480`).

The base callback has no observation declaration (`CircuitElm.java:982`); `CompositeElm.stepFinished()` forwards to child elements (`CompositeElm.java:326-328`). Overrides in this checkout are in `AmmeterElm`, `AntennaElm`, `AudioInputElm`, `AudioOutputElm`, `BoundedExternalLoadElm`, `DataRecorderElm`, `DiodeElm`, `LEDArrayElm`, `MosfetElm`, `PolarCapacitorElm`, `ProbeElm`, `ProtectionFuseElm`, `SevenSegElm`, `SRAMElm`, `StopTriggerElm`, `TestPointElm`, `TimeDelayRelayElm`, `TransistorElm` (nested element), `TransLineElm`, and `VoltageElm`; `A07SolverDeveloperVerifier` and `A10TemporalBatchVerifier` also define test subclasses. Since the callback is virtual and has access to simulator/element state, the call site cannot infer its read set from this interface.

`CircuitSolverExecutor.accepted` dispatches due `SolverEventQueue.Action`s (`CircuitSolverExecutor.java:195-200`). The generic action signature carries only scheduled and accepted simulation times (`SolverEventQueue.java:7`); its closure can capture arbitrary simulator state. Queue snapshot/restore, cancellation, scheduling and dispatch preserve event identity/order/state (`SolverEventQueue.java:34-45,63-101`), but carry no observation capability or wire-read declaration. Current in-tree scheduling callers are verifier/proof code (`A07ExecutionContractVectors.java:145-181`, `A07SolverDeveloperVerifier.java:186-204`, `A10TemporalBatchVerifier.java:47-53,111`, `RcTemporalWorkDeveloperVerifier.java:80`); the executor still exposes and dispatches the generic queue.

A10 is a concrete counterexample to assuming accepted actions do not read wire current: its event appends `wire.getCurrent()` (`A10TemporalBatchVerifier.java:47-53`). With no wire scope, the temporal path dispatches that action before the `calcWireCurrents()` at `CirSim.java:3458`, so the callback can see the prior cached wire current. Making `getCurrent()` lazily refresh during that action, or deferring the refresh across accepted steps, would change callback-visible values. Moving refresh before callbacks would also change the established observation point/order.

## Other observation contracts

`canDelayWireProcessing()` checks `Scope.viewingWire()` for regular and embedded scopes (`CirSim.java:3257-3266`); `Scope.viewingWire()` explicitly detects a plotted `WireElm` (`Scope.java:2044-2048`). `Scope.timeStep()` samples `elm.getScopeValue(value)` (`Scope.java:107-112`), while `CircuitElm.getScopeValue(VAL_CURRENT)` reads `getCurrent()` (`CircuitElm.java:909-912`). This gate therefore protects known scope readers only.

`SolverTimeObservationService` is another accepted-boundary observer, but its subscription contract is two `CircuitPostMeasurementEndpoint`s and it records their differential post voltage (`SolverTimeObservationService.java:20-23,100-108,132-146,212-220`). It has no wire-current observation mode. Product measurement routes through `CircuitMeasurementAdapter` and `InstrumentController` (`CircuitMeasurementAdapter.java:41-48`, `InstrumentController.java:762-768`).

## Safe-defer conclusion and requirements

There is no existing generic predicate that proves all accepted-step readers are independent of wire-current freshness. The only established safe boundary for the delayed owned path is the existing per-step refresh after callbacks and before the next accepted step; do not extend it across accepted steps on the basis of operation identity, event time, or queue snapshot/cancellation state. Keep solved voltage publication and each element's `calculateCurrent()` publication intact as established in the prior audit; this question concerns only the separate derived wire-current cache.

For a future generic gate, observation requirements must be declared by each relevant boundary owner: `CircuitElm.stepFinished()` implementations (including composite children), scheduled actions (including actions added during dispatch), and scope readers. Each declaration must state whether it needs fresh wire current at that accepted-step callback point; a missing declaration must conservatively require refresh. Aggregate the declarations per accepted step and refresh before the earliest reader while preserving current callback/event/scope order, cancellation and snapshot cleanup. No such API or declaration exists now. This is feasibility guidance only; it authorizes no Q30-specific or production optimization.
