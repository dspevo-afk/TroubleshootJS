# Passive pose admission worker notes

This packet adds a separate `RB56_BOARD_NORMAL@2` physical admission identity for the explicit orthogonal passive-pose interpretation. `RB56_BOARD_NORMAL@1` and `MEDIUM_BOARD_NORMAL@1` keep their existing identity and canonical bytes for pose policy 0. The new identity appends a bounded canonical field listing the four supported passive packages and `TOP/0,TOP/90`; the existing RB56 declaration for board population, isolation corridor, UAC, UFB, access, and routing remains intact.

The normal RB56 route admission now derives its contract from placement constraints. A focused passive-pose validator checks the selected MEDIUM_BOARD constraints, rejects policy/contract mismatches, retains TOP0 for generic and legacy passives, permits TOP0 for foreign passive packages, and permits TOP90 only for the four canonical packages under policy 1. It rejects other rotations, bottom mounting, foreign-package substitution, and turned foreign passives. The validator is called by the complete normal-geometry gate and can also be exercised directly by narrow negative fixtures that do not claim routed admission; the complete route still applies its existing package allowlist.

Identity consumers in the assigned scope now select explicitly: route issuance derives the contract from constraints; RB56 assembly checks the selected placement version, constraints, and admission identity; normal/default family registration remains pinned to `@1`; private request canonicalization selects the identity from its resolved placement interpretation. Dependency canonicalization emits `placement.passive-pose-policy=1` only for nonzero policy, leaving pose0 board dependency bytes unchanged.

The new `PcbPassivePoseAdmissionContractTest` includes literal placement/constraint identity checks, default version 15 versus explicit version 16 mapping, admission canonical compatibility checks, paired dependency-canonical checks, and direct positive/negative calls to the actual passive-pose validator for the canonical, foreign, mixed, turned, and bottom-mounted fixtures. Bottom-side negatives use a declared package that supports bottom mounting paired with passive component types, so they reach the policy validator instead of failing earlier package-mechanics construction. Its required success marker is `PASS: PCB passive pose admission contracts `.

Validation was static only. Source inspection confirmed the existing `PcbRotation` enum has the four cardinal values and no `degrees()` accessor; the test uses its enum values in messages. The focused contract test was not run, and no compile, route generation, normal owner admission, replay, full-14 fitness gate, or player qualification was run in this worker scope. In particular, full owner/replay evidence remains NOT RUN, and downstream qualification consumers remain for root integration.

The implementation is in the bounded task copy for root integration. No files were staged or committed.
