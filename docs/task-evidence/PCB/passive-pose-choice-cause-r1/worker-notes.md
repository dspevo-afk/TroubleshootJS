# Passive choice observer implementation handoff

This is the bounded observer for the fixed 15/16 candidate-1 comparison described in `proposal.json`. It records only values already computed by the existing planner path. It does not add placement visits, pose evaluation, clipping, fitting, scoring, random draws, registry creation, route calls, or outcome changes. The Java contract fixture is synthetic and is not physical-placement evidence.

## Capture lifecycle and sample

`PcbPassiveChoiceObserver.start(rootSeed, layoutSeed, placementVersion, reference)` creates a single active capture. `beginPlan` returns it only for requested candidate 1 with the matching layout seed. The planner hooks populate it in memory, and the owner calls `stop(capture)` from its paired route fixture's cleanup. The trial capture holds the stopped old capture in memory for equality matching; the old capture is not nested into emitted JSON.

The pure contract test emits one complete synthetic sample after all capture callbacks and `stop`: one line beginning `PCB_PASSIVE_CHOICE_PROTOCOL_SAMPLE ` followed by `Capture.json()`. The synthetic record is old mode, interpretation 15, policy 0, density 14, candidate 1, algorithm candidate 0, root seed `42`, layout seed `9001`, one declared/placed item, three recorded visits, and no reference. Expected lifecycle values are started/stopped/planBegan/planEnded true, plan begin/end counts 1, error count 0, error type null. Bounds are item count 1, actual visits 3, no overflow, with limits 128 items, 60,000 visits, and 512 exported visits per version. Its status is `COMPLETE` with no reason codes. The JSON carries the same schema as route captures; the sample is only a parser/protocol canary and must not be counted as a route row, one of the 14 physical source bindings, or evidence for either root seed's physical outcome. The test does not print any `PCB_PASSIVE_CHOICE_CAPTURE ` line.

The route owner should emit four real capture rows in the scheduled order: 42/15, 42/16, 3/15, 3/16. Each row pairs only within its root seed: the 16 capture refers to the corresponding stopped 15 capture. The root-owned independent reader is responsible for verifying those bindings against the unchanged physical route rows.

## Frozen JSON shape

Top-level keys, in order: `schema`, `marker`, `rootSeed`, `layoutSeed`, `interpretation`, `policyVersion`, `densityVersion`, `candidate`, `algorithmCandidate`, `mode`, `referenceAvailable`, `expectedPartCount`, `lifecycle`, `bounds`, `status`, `reasonCodes`, `sizing`, `sizingEqual`, `outline`, `compaction`, `firstDivergence`, `items`, `firstSelectedFootprintDivergence`, `divergenceVisits`.

`schema` is `pcb-passive-choice-observer-v1`; the JSON `marker` property is `PCB_PASSIVE_CHOICE_CAPTURE_V1`. Root/layout seeds are quoted signed decimal strings. Mode is `old` or `trial`. Nullable frame and comparison values are JSON `null`. Status is `COMPLETE` only after stop, one successful plan begin/end, matching declarations and placements, all item selection frames ended, required sizing/outline/pre/post-compaction frames present, no overflow, and no reason codes; otherwise it is `INCONCLUSIVE`.

Ordered nested keys:

- `lifecycle`: `started`, `stopped`, `planBeginCount`, `planEndCount`, `planErrorCount`, `planErrorType`, `planBegan`, `planEnded`.
- `bounds`: `maxItems`, `itemCount`, `maxVisits`, `actualVisitCount`, `itemOverflow`, `visitOverflow`, `maxExportVisitsPerVersion`, `exportOverflow`.
- `sizing`: `sourceCount`, `demandArea`, `courtyardArea`, `maxWidth`, `maxHeight`, `anchorWidth`. Area totals and signed seed values are quoted decimal strings where needed to avoid precision loss.
- `outline`: `targetArea`, `aspectIndex`, `aspectBits`, `compactFactorBits`, `spacingFactorBits`, `contentWidth`, `contentHeight`, `outline`, `outlineArea`, `boundaryX`, `boundaryFirstDemandBits`, `boundaryTotalDemandBits`, `boundaryFractionBits`.
- All rectangles use ordered keys `x`, `y`, `w`, `h`.
- `compaction` has `pre`, `post`; each plan snapshot has `candidate`, `demandArea`, `courtyardArea`, `evaluations`, `outline`, `footprints`. Snapshot footprint keys are `componentId`, `packageId`, `geometryVariantKey`, `geometryTransformKey`, `x`, `y`, `width`, `height`, `rotation`, `side`, `selectedKey`, `geometryFingerprint`.
- Each `items` record has ordered keys `componentId`, `declarationOrdinal`, `domainId`, `regionId`, `anchor`, `declaredAnchor`, `packageId`, `canonicalPassive`, `passivePolicyEligible`, `sourceGeometryKey`, `sourceGeometryFingerprint`, `sourceRotation`, `sourceSide`, `sourceX`, `sourceY`, `sourceWidth`, `sourceHeight`, `accessMargin`, `alternateGeometryKey`, `alternateGeometryFingerprint`, `alternateRotation`, `envelopeTOP0`, `envelopeTOP90`, `sizingDemandArea`, `sizingEnvelopeWidth`, `sizingEnvelopeHeight`, `placeOrdinal`, `orderKind`, `evaluationDelta`, `prefix`, `guidance`, `selectedSearch`, `fallback`, `poseStats`, `referenceOrigin`.
- Each prefix entry has `componentId`, `selectedKey`. Guidance keys are `hintXBits`, `hintYBits`, `connectedX`, `connectedY`, `preferredBeforeGroupX`, `preferredBeforeGroupY`, `preferredX`, `preferredY`, `group`, `direction`, `baseX`, `baseY`, `boundaryPackage`, `boundaryX`, `support`, `vacancies`, `vacancyPreference`, `vacancyPocket`, `sourceEnvelope`. Support has `ownerId`, `firstPadId`, `secondPadId`, `targetX`, `targetY`, `firstX`, `firstY`, `secondX`, `secondY`.
- `selectedSearch`: `selected`, `x`, `y`, `rotation`, `side`, `geometryKey`, `geometryFingerprint`, `scoreBits`, `fallbackUsed`, `visitCount`, `selectedKey`. `fallback` is null or has `minX`, `maxX`, `minY`, `maxY`, `columns`, `rows`, `total`, `start`; total is a quoted decimal string and start is an integer.
- `poseStats` has all four pose keys `DEG_0`, `DEG_90`, `DEG_180`, `DEG_270`. Each has `visits`, `legal`, `scored`, `minimumScoreBits`, `minimumVisitKey`, `incumbentUpdates`, `ringVisits`, `ringLegal`, `ringScored`, `fallbackVisits`, `fallbackLegal`, `fallbackScored`, `firstFallbackLegalKey`.
- `referenceOrigin`: `itemFound`, `oldSelectedRotation`, `oldSelectedX`, `oldSelectedY`, `oldSelectedGeometryKey`, `trialSameOriginDEG0`, `trialSameOriginDEG90`, `trialSameOriginDEG180`, `trialSameOriginDEG270`, `trialOldGeometryOriginVisits`, `trialOldGeometryOriginVisited`.
- `firstDivergence`: null or `stage`, `componentId`, `visitKey`. Stages are set at the earliest observed difference (including `sizing`, `outline`, `boundary`, `source-geometry`, `item-order`, `placed-prefix`, `guidance`, `visit-sequence`, `visit-template`, `requested-origin`, `grid-clipping`, `fit-result`, `score-result`, `incumbent-update`, `selected-footprint`, `compaction-output`).
- `firstSelectedFootprintDivergence`: null or `componentId`, `oldPlaceOrdinal`, `trialPlaceOrdinal`, `oldSelectedKey`, `trialSelectedKey`, `sourceGeometryEqual`, `sizingEqual`, `outlineEqual`, `boundaryEqual`, `samePlaceOrdinal`, `prefixEqual`, `guidanceEqual`, `comparable`, `reasonCodes`, `oldVisitCount`, `trialVisitCount`, `visitArraysComplete`, `exportOverflow`.
- `divergenceVisits`: null or `{old:[...],trial:[...]}`. Each actual visit event has `visitKey`, `kind`, `ordinal`, `ring`, `index`, `fallbackOrdinal`, `requestedX`, `requestedY`, `x`, `y`, `rotation`, `geometryKey`, `legal`, `scored`, `scoreBits`, `incumbentUpdate`. Ring/index are null for fallback; fallback ordinal is null for ring.

Only actual visited trials are represented. A failed `fits` visit is legal=false, scored=false, and scoreBits=null; this is a valid observation. A non-finite score on an actually scored legal visit adds an inconclusive reason. Every old visit is stored once. Trial visit records are retained in a per-item temporary vector for paired comparison. Capture stops at 60,000 visits per candidate, 128 item summaries, and 512 events per version for the first selected-footprint divergence. Exceeding a bound or missing a required frame yields `INCONCLUSIVE`; no partial trace can be reported as complete proof.

## Interpretation guards

`passivePolicyEligible` is emitted directly from presence of the prepared alternative template. Do not infer it from `domainId`; the pin-local branch requires requested candidate 1, repeated control regions, medium placement, and a non-anchor item. The four canonical passive package identities are the only eligible alternatives. Their source template is canonical TOP0 and even/odd visit ordinals select DEG_0/DEG_90. Other items retain their provider source rotation, including UFB DEG_180; the legacy path does not imply every candidate-1 source template is TOP0.

Requested ring coordinates are captured after the existing ring-zero vacancy substitution and before the existing `mediumGridOrigin` clipping. Captured x/y are the resulting trial's actual placed origin. This distinguishes requested-target changes from active-envelope clipping. Ring ordinals remain `ring*count+index`; fallback ordinals are the existing sequential fallback visit number. No score or pose is reconstructed from a production transform.

The `comparable` flag requires the same source geometry, raw outline, boundary inputs/result, place ordinal, placed prefix, and guidance. `sizingEqual` is retained as a separate flag so a local placement comparison can show equal outline/guidance despite a different aggregate demand. `referenceOrigin` reports only whether the old selected pose/geometry at its old origin appears among actual trial visits; it never evaluates an unvisited counterfactual. A matching local fit/score difference is attributable to the actual substituted pose only when all preceding context flags match. It does not establish global optimality or explain final route metrics by itself.

## Static checks and handoff status

The Planner hooks are limited to the candidate-1/matching-seed observer path and bracket existing plan, sizing, outline, item guidance, ring/fallback visit, score, selection, and compaction frames. They do not modify loop bounds, ordinal calculation, evaluation counters, comparisons, return values, or router calls. The old capture aliases its item visit vector, so each observed old visit is appended exactly once; the trial capture uses a bounded temporary vector.

The pure contract fixture covers schema/sample shape, lifecycle failures, missing item/end frames, earliest strict score minimum, fallback first-legal aggregation, paired first selected divergence, old selected-origin matching, non-finite actual scoring, visit and export caps, and source geometry immutability. Its Java source marker is `PASS: PCB passive choice observer contracts `. It has not been executed by this worker. No native planner/runtime, build, route, or gate output was run or reviewed here. Root owns final static review, line-ending normalization, the independent reader freeze, and all acceptance execution. The sample JSON itself is emitted by the test during the root-owned run and is intentionally not represented here as already observed output.
