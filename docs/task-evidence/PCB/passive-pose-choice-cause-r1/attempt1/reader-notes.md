# Independent reader handoff

`assess.py` is the independent reader for the bounded 15/16 candidate-1 passive-pose choice diagnosis. It consumes route rows and capture rows supplied by the caller; it does not launch Java, read hidden run logs, fit new layouts, or infer unvisited poses or origins.

The public handoff API is:

- `check_phase(text, receipt, timing, suites)` validates the maintained unit or route phase, its exact receipt and terminal report ordering, timing shape, suite manifest, and cleanup markers.
- `check_protocol_sample(unit_text)` requires one serialized `PCB_PASSIVE_CHOICE_PROTOCOL_SAMPLE ` line and validates its complete schema and synthetic sample details only. Its result includes `syntheticOnly: true`; it is not a physical source or route binding.
- `check_sources(unit_text)` validates the 14 literal old-source rows and trial-source inputs, then returns all 14 source bindings enriched with complete component ID/package inventory and lexicographic declaration ordinals.
- `assess_routes(route_rows, capture_rows, source_bindings)` requires the complete 14-root binding map, checks the four exact physical route reproductions, binds their source hashes/graph/intent/seeds, validates the four captures, and independently compares each old/trial pair.

The route assessment result separates evidence levels. `routeFidelity: PASS` means all four route rows match every sealed non-timing field. `captureFidelity: PASS` means all four capture records are complete, bounded, and internally valid. Overall `status` is `PASS` only when both checks pass; incomplete capture frames yield `INCONCLUSIVE` while the route result remains separately visible. `localAttribution` is `COMPARABLE` only when both root-pair summaries have a complete exported divergence trace and matching required context. Each root also reports its own attribution status; a context mismatch or missing comparison remains `INCONCLUSIVE`. This is evidence-fidelity output, not a policy-quality, route-acceptance, or packing-improvement claim.

Capture validation enforces the frozen ordered JSON schema, signed-long seeds, lifecycle/frame counts, 128-item/60,000-visit/512-event bounds, finite IEEE score bits, candidate/version identities, complete item/source inventory, exact source versus alternate geometry keys, per-pose summary counters and minima for internal consistency, eligibility parity, provider-pose preservation, prefix snapshots, guidance shapes, compaction snapshots, and first selected-footprint divergence flags/reason order. A legal fit must have its actual finite score; `fits == false` with no score is an ordinary observation. Scores may be negative, and requested origins may be negative. The selected prefix key follows `FootprintSnapshot.selectedKey()` and omits `geometryContractVersion`, while a search event's geometry key includes that version.

Independent event-level replay is limited to the first selected-footprint difference's fully exported old/trial event arrays. There the reader verifies that each selected placement came from an observed legal scored visit, recomputes strict minima and incumbent changes, checks old-origin counts against actual trial visits, and derives the event-stage difference. Summary counters and minima for other items are observer-reported and checked for internal consistency, not independently reconstructed. No counterfactual fit or score is performed. `sizingEqual` is independently recomputed from aggregate sizing and per-item size values, including both TOP0/TOP90 envelopes; it is reported separately and is not a prerequisite of the observer's local `comparable` flag. Source geometry is checked before sizing because declaration hooks establish that order. Raw outline equality compares only the outline rectangle; boundary inputs are compared separately.

The Python canaries use the exact-hash-bound earlier policy unit report at the path and SHA recorded in `assessment-canaries.json`, solely as already-published source-binding input. All new route and capture rows are synthetic reader fixtures. `assessment-canary-results.json` records that no new native choice outputs were consumed. The synthetic root 42 case deliberately has an outline context mismatch; the root 3 case has equal outline but a separate sizing mismatch, exercising the distinction between capture fidelity and local comparability.

## Handoff limits

No native choice output existed when this reader was implemented. Root owns source freeze, the fresh unit and paired route runs, the real protocol-sample validation, the post-run `assessment.json`, final review, and all acceptance statements. The reader has not established a local cause for either physical root, a better policy, a full-board improvement, or any owner/replay/player/manufacturing behavior.
