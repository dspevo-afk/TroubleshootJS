# Private routed passive feasibility census reader

This leaf owns the strict offline reader and its pure in-memory canaries for
the closed two-root physical feasibility census. It does not implement or
execute the Java construction, bridge, wrapper, native trial, or physical
verifier.

`assess.py` pins protocol SHA-256
`fe580517a9c104ef9b22b3961826e4d6ca49c82b509a88a7bf8484baa07239e1`, the
prior census reader SHA-256
`f9b79e21875864aecde86e41d1b49d955d6f9201585cebebf462ffd87fb82229`, both
suite manifests, all ten published input hashes, and all seven classification
owner hashes. It composes the pinned prior reader for the unchanged old census
boundary, including strict JSON, typed equality, selected cases, whitespace,
and the old three-report route oracle. It then requires the current old census
rows to be typed-equal to their sealed published summaries before reading the
new feasibility rows.

The routes phase requires exactly eight reports in root order 5 then 2:
`WHITESPACE`, old `CENSUS`, old `CASE`, and current feasibility `CENSUS` for
each root. Root 5 is an exact `NO_TARGET` zero-construction row. Root 2 is an
exact 31-direction census derived from the original target callback; every
move is checked against the sealed canonical order and its analytic/actual
copper delta. Each candidate must preserve the source component, pad, trace,
and area counts, derive its affected traces from sealed incident indices,
carry `NOT_ASSIGNED_PRIVATE_CANDIDATE`, and use geometry different from the
source. The first row must retain the exact C5 courtyard rejection literal.
The source area, copper length, trace count, geometry, and live graph are also
cross-checked against the unique matching seed-2 successful-route-pool event.

Stage semantics are pinned explicitly: the outer `GEOMETRY` call may report a
nested two-layer or route-quality rejection with `geometryValidated=false`;
`TWO_LAYER` is accepted only for the explicit later call after geometry has
completed. The removed `DRILL_LAND_CLEARANCE` reason is rejected. Unknown
errors, budgets, malformed construction, cancellation, missing proof, and
source/native failures do not become accepted physical rows.

For validated rows, the reader requires all validation flags, 9,045 pad pairs,
145 route sources, equal valid source/candidate provenance hashes, and equal
source/candidate reachability hashes. It independently anchors reachability to
all 135 published seed-2 pad/net facts: stable pad-ID sorting, UTF-16-code-unit
length fields, every pair, net-equality bits, and the UTF-8 `R1` stream produce
9,045 pairs, 175,409 bytes, and SHA-256
`9a1081bec94f99493fff9bf12f2653f27d18db64b4b49b9b2ea826094c4d46b7`. The
offline reader checks the native provenance and endpoint/unrelated-geometry
flags but cannot reconstruct absent candidate trace paths or independently
recompute the native provenance hash.

The final pure canary receipt reports 70 cases: 7 positive and 63 rejected.
It includes all-rejected and mixed synthetic route fixtures, the literal
reachability oracle, nested and explicit stage cases, the exact C5 rejection,
foreign graph/net anchors, candidate/source metrics and geometry, move/filter/
order/hash drift, proof flags and null shapes, classification catalog,
timing/aggregate/phase/receipt order, stale unit prerequisite, duplicate keys,
native failure/timing/exit markers, and protocol/published-input pin drift.
Synthetic candidate values are schema fixtures only; no native feasibility
trial was run by this leaf. The receipt records status `PASS`, fixture counts
