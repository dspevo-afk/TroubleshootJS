# P09 implementing-root review

This is the implementing root's integrated source review plus independent
executable geometry, copper/solver, diagnostic and report checks. No separate
human or subagent review is claimed.

The normal staged entry rejects before taking ownership or detaching the original
solver graph. Physical admission and publication revalidate the policy; legacy
normal live/composition admission also retains it. A rejected fresh candidate is
disposed by the existing generation owner, which checks that no candidate element
belongs to the live graph. Prototype developer ownership is not converted into
normal ownership. Unknown policy identity/version cannot silently select a default.

The envelope is a necessary upper/lower-bound check, not a proof cache. Its registry
contains no seed or family whitelist. Catalog identity is typed, package counts are
bounded independently of total population, board arithmetic uses long products,
and NaN route scores reject. All currently available difficulty profiles obtain
the same physical policy; unavailable profiles remain unavailable. Dependency v9
includes the full envelope and resource policy, while request v2 carries identity.

The independent validator still owns actual package correspondence, lead/pad
geometry, global copper connectivity and clearance. The explicit missing-copper
negative passes the envelope bounds and then fails geometry: a useful falsifier
against treating a part count, route score or certificate string as physical truth.
No live solver readings or diagnostic behavior were replaced by geometry metrics.

The normal view policy retains actual face/exposure checks and existing immutable
projection ownership; hidden copper cannot become a normal target merely because
it shares screen coordinates or a logical net label. Prototype via/trace mouse
measurements and face invalidation are checked separately in the compiled browser.
There is no live-cut repair expansion, SMD production qualification or mains-safety
rating implied by these drawing-unit limits.

P09's structural corpus is deliberately separated from gameplay proof. A correction
to the single-face assumption occurred on the first calibration row, before any
held-out execution. The post-freeze exposure hardening is disclosed separately;
no numerical bound was relaxed against held-out failures. Seed 23 exceeds board
area (and also route score); seed 509 exceeds unique copper length. Both remain

with the frozen 54-row corpus. This supports rejection of normal two-layer/link
adoption for this epoch, not a claim that such boards are inherently impossible.

Resource figures distinguish deterministic caps, JVM validation timings, sampled
process heap and compiled-browser observations. The old Quick Play test budget
remains unchanged; only its scheduling moved first after load-sensitive full-run
timeouts. The Python verification prerequisite was repaired with a verified
unpacked task-local runtime, not OS permission, authentication or sandbox changes.

Remaining scope boundaries: arbitrary candidate-seed Quick Play admission, larger
production envelopes, new package/pose/domain mixes, and proven medium/large-board
layer adoption require their own evidence. These are not silently marked complete.
