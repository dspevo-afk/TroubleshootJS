# Returned pre-output validation-child failures

Frozen before final host execution. The EXTRA_INPUT_HASH expected control must
reject in the host's bounded exact extra-file hash prevalidation, before invoking
the auditor. Thus none of the five expected controls needs an unpersisted inner
process receipt; their exact single-line rejection frame remains unchanged.
Strict Python schema/source preflight still precedes successful output creation.

If a DIFFERENT unexpected pre-output validation child returns a genuine failing
receipt, preserve that unchanged receipt and measured call wall in an additional
stderr line P8_CANARY_HOST_PROCESS_FAILURE followed by compact JSON. Exit nonzero
with the normal failure frame too. This path cannot qualify as any expected
one-frame negative. Keep the actual raw child fields, not a synthetic empty
receipt; enforce the64KiB line/8MiB aggregate bounds. If it cannot fit, mark the
missing full evidence as a distinct failure. When output exists, preserve the
same genuine receipt in host-failure.json. API throws without a returned receipt
follow R2 instead. No extra output directory or stdout diagnostic is authorized.

These exception-only diagnostics do not change native, cleanup or reader caps,
source binding, expected negative codes or successful result framing. They close
failed-call evidence gaps while preserving the no-output-mutation expectation.
