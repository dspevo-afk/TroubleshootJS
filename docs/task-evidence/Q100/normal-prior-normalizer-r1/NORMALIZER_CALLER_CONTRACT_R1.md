# Normalizer caller boundary

The pure normalizer accepts authenticated byte values and externally observed
facts. A self-hash proves consistency of a supplied object; it does not prove
that its contents describe the host. The caller must establish the following
boundary before claiming normal-prior qualification.

1. Freeze and verify the actual normalizer, fixed-role reader, context codec,
   generated pure kernel and extraction provenance SOURCE bytes. Load callbacks
   only from those exact current modules, with all five kernel and three codec
   members bound to the reviewed functions. A callable check or a provenance
   digest-shaped string alone is not authentication.
2. Freeze a SOURCE-only manifest before creating current input DATA. It contains
   implementation/contract/tool identities, never current generated DATA,
   classes, run IDs, producer results or a producer manifest that consumes DATA.
   Authenticate its actual bytes. Supply its SHA in the exact three-field
   currentSourceAuthority (schema, sourceSha256, authoritySha256). Its self-hash
   excludes authoritySha256. This object stays outside canonical context and
   is returned as a detached copy. Later runtime identity remains separate.
3. Independently fix the private N/D roots and record the operational phase
   transition before reading the exact 20 roles. Use the qualified fixed-role
   reader and its unchanged published allowlist. Authenticate every role's
   bytes before any role decode. Recheck all inputs after normalization.
   Do not follow any path found in historical source/run/class metadata.
4. Establish actual source/tool byte facts for the selected historical tools.
   Compare bytes and SHA against the reviewed pins. In addition to the harness
   and process-module hashes, verify the selected process-module path is
   embedded in the authenticated harness SOURCE bytes, preserving the old host
   check. The pure normalizer receives byte facts, not tool bodies, and cannot
   perform this filesystem/content-link check itself.
5. Observe exact call-directory closure (seven names each), native-data closure
   (op-1.jsonl and result.json only), and absence of the two calls' process roots
   and raw stdout/stderr log paths. Bind paths to the authenticated process
   receipts. Preserve canonical/reparse/identity checks. Freeze the actual
   observation evidence and its SHA; do not invent absence or an observation
   from a digest-shaped placeholder. Synthetic test facts are not host proof.
6. Freeze the complete outer normalizer authority, excluding its own digest
   field when hashing. It binds roots, SOURCE authority, kernel provenance,
   source bindings, tool facts and resource facts. Verify it again after use.
   Its resource observations may follow authenticated prior decoding; its
   current SOURCE manifest must precede current generated DATA.

Only after the source-reviewed normalizer and reader positive/negative gates
pass may a separate journal enable the fixed normal-only read phase. Neither
this contract nor successful synthetic tests alone opens it. Old D descriptor,
result and generated-input DATA, old builders/CLIs/modules, protected/held-out
bodies and manifest recursion remain denied. The one genuine original plus
exactly NULL/OBSERVE remains separately gated and unspent.

The normalizer independently revalidates historical manifests and receipts,
qualification cross-checks, P07 operation/PAD/reference, stable order, N runs,
work and cleanup. Actual pinned-prior acceptance and later current host/native
assembly require their own evidence. No production/GWT, Player, electrical,
population, full-D/H1 or playable100 qualification follows from this component.
