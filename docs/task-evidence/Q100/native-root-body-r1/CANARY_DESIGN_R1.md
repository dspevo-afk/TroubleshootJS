## Single-summary protocol and cleanup

Top-level keys are mode, status, names, cases. names is the exact frozen ordered
string array. cases is the same-length ordered array of scalar-only records with
exact fields name,status,units,copies,chunks,groups,observedItems,operationNanos,
cleanupNanos,cleanupDisposition,error,cleanupError. Integers are nonnegative;
error/cleanupError are bounded escaped class/message text and empty on PASS.
observedItems is the trap-child observation count (zero on PASS); it does not
claim that independent root assertions perform no root reads.

Counters are sampled after case operation and before cleanup. groups counts closed
groups only, so it is 1 for the final-allocation-fee rejection and ordinary unit
roll, and 0 for all other passing records. Cleanup finishing is outside that
counter delta. operationNanos ends before cleanup scalar sampling/finish;
cleanupNanos independently includes those read-only samples and cleanup.

Expected PASS dispositions:

- NONE: root_null_meter_guard (no meter created).
- ALREADY_CLOSED: root_copy_allowance_12_reject,
  root_copy_admission_units_13_before_allocation_fee, root_group_640_reject.
- EXPECTED_EXPIRED_METER_DISCARDED: root_expired_operation_reject and
  root_expired_group_reject. The latter intentionally abandons the expected-open
  failed meter with no OS resource; it never calls finish on that expired group.
- CLOSED: all other SMOKE/SUITE cases; SetupMeter.finish returns normally and
  read-only observation proves open=false.

The discard marker is assigned only after the expected exception and all state
assertions succeed. Unexpected errors do not gain that disposition. Any actual
cleanup exception sets FAIL/CLEANUP_FAILED with cleanupError; it is never suppressed
or represented as successful cleanup. Records continue after operation failure
to preserve evidence, and the overall process exits 1 if any record fails.
