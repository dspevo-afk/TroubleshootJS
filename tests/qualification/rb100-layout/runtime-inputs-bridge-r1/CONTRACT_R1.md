# Runtime identity carrier bridge

This prerequisite adds Parent.runtimeInputs(Arguments) to the existing native
adapter. It returns the existing owner Inputs carrier with the exact references
from runId, sourceManifestSha256, wireContractSha256 and outputDir. Context hash
and the validated expected Map retain their existing separate owners. No new
carrier, schema, parser, resolver, expectation clone or Meter is introduced.

Arguments is the existing private-constructor holder produced by V2 parse. The
bridge requires that already-validated holder and rejects null before reflective
constructor lookup with IOException RUNTIME_INPUT_ARGUMENTS. It does not repeat
identity/path validation, authenticate hash values or reserve the directory.
The actual native constructor has three String parameters and one Path; its
four assignments preserve reference identity. Lower internal field names remain
runId/manifestSha/wireSha/data. Selected owner consumers establish data's output
role by export use and op-1.jsonl resolution; no broader receipt safety follows.

The pinned Parent loader initializes the current owner with Charset UTF-8 and two
UUID/SHA regex Patterns only. Inputs, Meter, OriginalArm and CaptureData have no
static initializer in the inspected code. Their type loading is not construction
of those objects. Only the real Inputs carrier may be constructed here; no
OriginalArm, Meter, graph, Session, factory DATA or capture operation is invoked.

This is a carrier-only mapping boundary. It does not accept an expected Map as
executable inputs. It creates no Meter, charges no units/copies and qualifies no
original-wrapper prepayment or metered caller sequence. Existing runtime
preflight and primitive VM costs are not a new logical-copy fee model. Before
normal use, the caller must establish actual producer-start/identity authority
and all required wrapper controls/copies under the existing budget owners. The
selected captureOriginal prefix already enters CaptureData and live budget work;
that method is deliberately outside this mapping test. No accounting limit or
oracle changes. Both main and assemble remain their exact throw-only methods.
